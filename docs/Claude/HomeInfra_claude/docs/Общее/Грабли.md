# Грабли и что они означают

Реальные ошибки с этой миграции. Полезны не столько сами рецепты, сколько принципы за ними.

## `does not provide attribute 'nixosConfigurations."X"'`

Имя после `#` — это **имя конфигурации во flake**, не хост и не пользователь. Без `#` подставляется текущий hostname.

Лечение: привести к одному имени `nixosConfigurations.<имя>` и `networking.hostName`. Посмотреть, что объявлено: `nix flake show ~/nixos`.

## `The option '...' does not exist`

**Модуль = объявление опций.** Пока модуль не в `imports`, любая его опция не существует, даже если синтаксис верный. Обратное безобидно: импорт без использования просто ничего не делает.

Так вылезли обе ошибки с DMS: сначала `programs.niri` (нужен `niri-flake`, в nixpkgs `programs.niri` живёт только на уровне системы и умеет лишь «поставить и включить»), потом `programs.dank-material-shell.niri` (принадлежит модулю `dms.homeModules.niri`, который я убрал, а блок оставил).

Подсказка `Did you mean ...` в конце ошибки — это список реально объявленных соседних опций. Ей стоит верить.

## `attribute 'X' missing` против `undefined variable 'X'`

- **undefined variable** — переменной нет в области видимости. Обычно забыт аргумент в шапке файла: `{ config, pkgs, lib, inputs, ... }:`
- **attribute missing** — объект есть, поля в нём нет. Обычно забыт input во `flake.nix`.

Так вылезло `attribute 'nixpkgs-unstable' missing`: оверлей ссылался на input, которого в inputs не было.

## `file not found`, хотя файл лежит на диске

Flake в git-репозитории видит **только файлы, известные git**. Новый файл без `git add` для Nix не существует. Коммит не обязателен, индекса достаточно.

## `warning: Git tree is dirty`

Не ошибка. Значит, есть незакоммиченные изменения и сборка не привязана к коммиту. Собирается то, что на диске.

## `evaluation warning: 'greetd.tuigreet' was renamed to 'tuigreet'`

Пакеты переезжают между релизами. Пока warning, в следующем релизе станет ошибкой. Чинить сразу, чтобы не копить.

## Home-manager делает файлы read-only

Всё под управлением home-manager — симлинк в `/nix/store`. Поэтому `~/.config/niri/config.kdl` намеренно оставлен обычным файлом: правки применяются мгновенно, `niri validate` работает, пересборка не нужна. Переводить под home-manager, когда конфиг устаканится.

## Claude Code не может обновить сам себя

В `/nix/store` писать нельзя, автообновление молча фейлится. Это нормально: обновление через `nix flake update` + пересборку. Пакет берётся из `nixpkgs-unstable` через оверлей `pkgs.unstable.*`, чтобы не протухал на стабильной ветке.

## Обозначения на будущее

- `stateVersion` — не версия ОС, а маркер формата данных. Не менять никогда.
- `hostId` — по нему ZFS решает, её ли пул. Уникален на каждой машине.
- Систему в NixOS почти нельзя уронить насмерть: старое поколение выбирается в меню загрузки.
