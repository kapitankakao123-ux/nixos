# Структура репозитория и команды

## Раскладка

```
~/nixos/
├── flake.nix              # хосты объявлены ОДИН раз → nixosConfigurations + ноды colmena
├── flake.lock             # точные коммиты всех inputs. Коммитить обязательно
├── modules/               # ЧТО машина умеет
│   ├── common.nix         #   nix, локаль, юзер, ssh — на всех
│   ├── desktop.nix        #   niri + DMS + звук + шрифты + home-manager
│   ├── storage.nix        #   ZFS, samba/nfs
│   ├── virtualisation.nix #   libvirt/KVM
│   ├── kiosk.nix          #   cage + браузер на весь экран (rpinix)
│   └── backup.nix         #   sanoid + syncoid
├── home/                  # окружение пользователя
│   ├── common.nix         #   DMS и дотфайлы — одинаковые везде
│   ├── kitjet.nix
│   └── gadnix.nix
├── hosts/                 # КАКАЯ машина что из этого включает
│   ├── kitjet/{default.nix, hardware-configuration.nix}
│   ├── rpinix/default.nix
│   └── gadnix/{default.nix, hardware-configuration.nix}
└── docs/                  # этот vault
```

Правило раскладки: `modules/` — возможности, `hosts/` — их выбор. Новая общая настройка идёт в `modules/`, специфика машины — в `hosts/`.

## Роли файлов

- **flake.nix** — источники (`inputs`) и что собирать (`outputs`). Пакетов в нём нет.
- **configuration.nix / hosts/\*** — система: ядро, драйверы, службы, пользователи. Всё, что от root, до логина или общее для всех.
- **home/\*** — пользователь: `~/.config`, дотфайлы, прикладные программы.

Критерий, куда класть пакет: нужен от root, до логина, тянет systemd-юнит или udev-правила → система. Иначе → home.

## Где живёт сам репозиторий

Вопрос «локально или в интернете» — ложная дихотомия: в git копия есть на каждой машине, где ты его клонировал. Разница только в том, **какая копия считается точкой обмена** (remote), через которую машины видят правки друг друга.

Раскладка:

- **Рабочая копия — на той машине, за которой сидишь и с которой деплоишь.** Сейчас это `kitjet:~/nixos`. Когда поднимется `gadnix` — там будет свой клон того же репозитория. Напрямую друг с другом они не синхронизируются, только через remote.
- **`rpinix` клон не нужен.** Colmena собирает конфиг на машине-деплойере и отправляет готовые пути по ssh; на целевой ноде git не требуется.
- **Сборка идёт из локального пути** (`nixos-rebuild switch --flake ~/nixos`), а не из URL. Иначе каждую правку пришлось бы коммитить и пушить до проверки.

Решение: **`origin` — приватный репозиторий на GitHub, плюс зеркало bare на `kitjet`.**

Почему нужен именно интернет-remote, а не только bare-репозиторий дома:

- Установка `gadnix`/`rpinix` начинается с «достать конфиг». Если единственная копия лежит на `kitjet`, а он выключен или как раз переустанавливается — остаёшься с флешкой и без конфига.
- Offsite-копия: пожар, кража или сдохший NVMe не уносят с собой всю инфраструктуру.
- Доступ снаружи дома, без VPN.

Приватный хостинг безопасен при соблюдении правила «секреты в git не кладём»; после подключения `sops-nix` секреты попадут в репозиторий уже зашифрованными — это нормально даже для публичного репо.

Зеркало на `kitjet` — на случай, когда интернета нет, а собрать надо:

```bash
# на kitjet, один раз
git init --bare /tank/git/nixos.git

# в рабочей копии
git remote add origin git@github.com:<логин>/nixos.git
git remote add kitjet /tank/git/nixos.git
git push origin main && git push kitjet main
```

`/tank/git` — датасет ZFS, значит он попадает в снапшоты sanoid и в реплику на `rpinix` вместе с остальными данными. Отдельного бэкапа репозиторию не нужно.

**Vault `docs/` кладём в тот же репозиторий**, а не рядом: заметки описывают ровно то состояние конфига, что лежит в соседних файлах, — расходиться им незачем, и вопрос «где бэкап vault» закрывается тем же push.

## Команды

```bash
colmena apply                 # раскатать на все машины
colmena apply --on rpinix       # на одну
colmena apply-local           # на ту, за которой сидишь
colmena build                 # только собрать, не катить

sudo nixos-rebuild switch --flake ~/nixos          # локально, по hostname
sudo nixos-rebuild test --flake ~/nixos            # применить до перезагрузки
nix flake update                                   # обновить все inputs
nix flake update nixpkgs                           # обновить один
nix flake show ~/nixos                             # какие конфигурации объявлены
```

Рабочий цикл: правка → `git add` новых файлов → сборка → если завелось, `git commit`. Коммит **после** успешной сборки, чтобы в истории лежали только рабочие состояния.

## Правила, нарушение которых стоит вечера

- **`git add` для каждого нового файла.** Flake в git-репозитории видит только файлы, известные git. Не добавил — «file not found», хотя файл лежит на диске. Коммит не нужен, индекса достаточно.
- **`networking.hostId` уникален на каждой машине.** По нему ZFS решает, её ли это пул.
- **`system.stateVersion` не меняется никогда.** Это маркер формата данных, а не версия ОС.
- **Имя после `#` — это имя конфигурации во flake**, не хост и не пользователь. Совпадает с `networking.hostName` → можно опускать.
- **Секреты в git не кладём.** До появления `sops-nix` — только пути к файлам вне репозитория.
