# Контейнеры на kitjet

> **Статус: работает** (2026-09-14). Первый контейнер — `pvzge`
> (PvZ2 Gardendless), порт 8080. Развёрнут декларативно, `docker run`
> руками не выполнялся ни разу.

## Принцип: контейнер описывается, а не запускается

`docker run` создаёт контейнер, о котором знает только демон docker.
Перезагрузка, перенос на другую машину, «что у нас вообще крутится» — всё
это превращается в археологию. Поэтому то же правило, что и для LXC
(см. CLAUDE.md): **контейнеры описываются в конфиге**, systemd поднимает их
сам, состав машины виден в git.

Механизм — `virtualisation.oci-containers`. Для каждого контейнера NixOS
генерирует systemd-юнит `docker-<имя>.service` с `ExecStartPre`, который
сам тянет образ.

## Где что лежит

| | Файл | Почему там |
|---|---|---|
| Сам docker (демон, группа) | `modules/virtualisation.nix` | общая возможность машины |
| Конкретный контейнер | `hosts/kitjet/default.nix` | роль именно этой машины |
| Порт в firewall | `hosts/kitjet/default.nix` | рядом с контейнером, который его занял |

**backend = `"docker"`, не podman.** На kitjet docker уже включён, а
`oci-containers` умеет только ОДИН backend на машину. Podman остаётся в
`modules/container.nix` для `rpinix` — этот модуль на kitjet не импортируется.

## Пример: pvzge

```nix
virtualisation.oci-containers = {
  backend = "docker";
  containers.pvzge = {
    image = "docker.io/gaozih/pvzge:v0.12.1";
    ports = [ "8080:80" ];     # снаружи 8080 → внутри 80
    autoStart = true;
  };
};

networking.firewall.allowedTCPPorts = [ 8080 ];
```

Три вещи, которые стоит понимать в этих семи строках:

1. **Тег прибит гвоздями.** `:latest` кажется удобнее, но nix не знает, что
   тег переехал: образ всё равно не обновится сам, зато на разных машинах
   и в разное время приедет разное. Обновление = правка версии здесь и
   повторный деплой. Ещё строже — по digest:
   `image = "docker.io/gaozih/pvzge@sha256:aa42d902aebf…"`.
2. **Порт открывается отдельно.** У `oci-containers` нет `openFirewall`,
   как у `services.jellyfin`. Пробросил порт — не забудь про firewall,
   иначе игра будет доступна только с самой машины.
3. **`docker.io/` в начале обязателен** для podman и не мешает docker —
   пишем всегда, чтобы конфиг не зависел от backend'а.

Развернуть — с deskjet, одной командой:

```bash
colmena apply --on kitjet
```

Проверить:

```bash
ssh root@kitjet.local systemctl status docker-pvzge
ssh root@kitjet.local docker ps
curl -o /dev/null -w "%{http_code}\n" http://kitjet.local:8080/
```

Играть — <http://kitjet.local:8080> с любой машины в домашней сети.

## Первый запуск долгий

Образ pvzge — **1.1 ГБ** в сжатом виде (игровые ассеты). `systemctl status`
покажет `active (running)` сразу, но это работает `docker run`, который ещё
качает слои: `docker ps` пуст, порт закрыт. Journal пишет только про
завершённые слои:

```bash
journalctl -u docker-pvzge -f
```

Это не ошибка, просто подождать. Дождаться по-человечески:

```bash
until docker ps --format '{{.Names}}' | grep -q pvzge; do sleep 10; done
```

## Как добавить следующий контейнер

1. Найти образ и понять три вещи: какой порт слушает внутри, нужны ли тома,
   нужны ли переменные окружения. Обычно всё это есть в `docker run` из
   README проекта — его и переводим построчно:

   | `docker run` | oci-containers |
   |---|---|
   | `-p 8080:80` | `ports = [ "8080:80" ];` |
   | `-v данные:/config` | `volumes = [ "данные:/config" ];` |
   | `-e TZ=Europe/Moscow` | `environment.TZ = "Europe/Moscow";` |
   | `--network=host` | `extraOptions = [ "--network=host" ];` |
   | `-d` | `autoStart = true;` (по умолчанию) |

2. Дописать в `containers.<имя>` в `hosts/kitjet/default.nix`.
3. Открыть порт в `networking.firewall.allowedTCPPorts`.
4. `git commit` → `colmena apply --on kitjet`.

**Тома для данных**, если контейнер их просит: именованный том
(`"имя:/config"`) живёт в `/var/lib/docker/volumes` и в бэкап ZFS не попадает.
Для всего, что жалко потерять, лучше путь на пуле: `"/tank/apps/имя:/config"`.

## Грабли

**`error: cannot update unlocked flake input 'hive' in pure mode`** — colmena
падает ещё до сборки, если в рабочей копии есть незакоммиченные изменения.
Она копирует flake во временный каталог и ссылается на репозиторий как на
вход `hive`, а грязное дерево заблокировать нельзя. Лечение: `git commit`
(одного `git add` не хватает). Правило «коммит после успешной сборки»
здесь превращается в «коммит после успешного `nix eval`, деплой после коммита».

**`docker ps` пуст под `gadjet`** — членство в группе `docker` применяется
при входе в сессию, а не мгновенно. По ssh проще сразу `root@kitjet.local`:
ключ root'а прописан в `modules/common.nix`.
