# ZFS на kitjet — пошагово

Гайд по созданию пула `tank`. Статус выполнения — в чек-листе [[kitjet]].

## Железо: важная поправка

Изначально считалось, что в машине три NVMe. **Это не так.** NVMe ровно один — системный:

| Устройство | Модель | Размер | Тип | Роль |
| --- | --- | --- | --- | --- |
| `nvme0n1` | NE-512 2280 | 512 ГБ | **SSD (NVMe)** | ОС, btrfs. Не трогаем |
| `sdb` | WDC WD10EZRX-00L4HB0 | 1 ТБ | HDD, SATA | половина зеркала `tank` |
| `sdc` | ST1000DM003-1CH162 | 1 ТБ | HDD, SATA | половина зеркала `tank` |
| `sda` | Hitachi HDS721050CLA362 | 466 ГБ | HDD, SATA | свободен |

Проверка типа диска: `lsblk -d -o NAME,SIZE,ROTA,MODEL,TRAN` — колонка `ROTA` (rotational): `1` = шпиндель, `0` = SSD.

Это меняет планы: HDD хороши под медиа, архив и реплики (последовательное чтение), но плохи под образы виртуалок (случайный доступ). Диски под VM надо искать отдельно — см. «Что дальше».

## Раскладка и почему так

**Решение: `tank` = зеркало из `sdb` + `sdc`. `sda` в пул не входит.**

Почему зеркало, а не raidz1 из всех трёх:

- raidz1 равняется по **самому мелкому** диску. С дисками 466 ГБ + 1 ТБ + 1 ТБ получится 3 × 466 ГБ, из них 932 ГБ полезных — и при этом больше гигабайта на двух терабайтниках просто пропадает.
- Зеркало 2 × 1 ТБ даёт те же ~1 ТБ полезных, но переживает смерть любого диска, читается вдвое быстрее и восстанавливается копированием, а не пересчётом чётности.
- Расширять зеркало проще: докупил пару дисков — добавил вторым vdev, ёмкость сложилась.

`sda` остаётся вне пула специально. Впихивать его третьей «ногой» в зеркало смысла нет (ёмкость не растёт), а отдельный пул из одного старого диска без резервирования — место, куда нельзя класть ничего ценного.

## Порядок действий

Важно: сначала конфиг и пересборка, потом создание пула. `zpool` — часть пакета ZFS, которого в системе нет, пока ZFS не включён. Именно поэтому «zpool: command not found» — это не сломанный PATH.

### 1. Сохранить старые данные

`sdb` и `sdc` — **одна** btrfs-ФС из двух устройств (`Total devices 2`), ~128 ГиБ данных. Стирание любого из дисков убивает её целиком.

```bash
btrfs filesystem show                    # сколько устройств и данных
sudo rsync -a --info=progress2 \
  --exclude='$RECYCLE.BIN' --exclude='System Volume Information' \
  /run/media/gadjet/<uuid>/ /home/gadjet/_migration/
```

### 2. Включить ZFS в конфиге

`modules/storage.nix` импортируется в `hosts/kitjet/default.nix`. Ключевое:

```nix
boot.supportedFilesystems.zfs = true;
boot.zfs.extraPools = [ "tank" ];
boot.kernelPackages = config.boot.zfs.package.latestCompatibleLinuxPackages;
```

И в `hosts/kitjet/default.nix`:

```nix
networking.hostId = "ab1bac40";   # head -c 8 /etc/machine-id
```

**Ядро.** ZFS — модуль вне дерева ядра, он всегда отстаёт от свежих версий. Строку `boot.kernelPackages = pkgs.linuxPackages_latest` пришлось убрать: с ней сборка падает на «zfs not supported on kernel X». Теперь ядро выбирает `modules/storage.nix`, привязывая его к версии ZFS.

**hostId.** ZFS пишет его в метаданные пула и при импорте сверяет с текущим. Совпало — пул мой, можно монтировать. Не совпало — пул считается чужим (вдруг он смонтирован на другой машине по SAS?) и требует `import -f`. Менять после создания пула нельзя.

### 3. Пересобрать

```bash
cd ~/nixos
git add -A . ':!docs'
sudo nixos-rebuild switch --flake .#kitjet
```

Меняется ядро — нужна перезагрузка, чтобы модуль ZFS загрузился:

```bash
sudo reboot
zpool version    # проверка, что утилиты появились
```

### 4. Стереть диски

```bash
sudo umount /run/media/gadjet/<uuid>       # udisks2 может примонтировать заново
sudo wipefs -a /dev/sdb /dev/sdc
```

Если на диске был LVM (у `sda` — группа `Gbackup`), сначала убрать его, иначе подписи вернутся:

```bash
sudo vgremove -f Gbackup
sudo pvremove -ff /dev/sda
sudo wipefs -a /dev/sda
```

### 5. Создать пул

```bash
sudo zpool create -f \
  -o ashift=12 \
  -O compression=zstd \
  -O atime=off \
  -O xattr=sa \
  -O acltype=posixacl \
  -O mountpoint=/tank \
  tank mirror \
  /dev/disk/by-id/ata-WDC_WD10EZRX-00L4HB0_WD-WCC4J1771636 \
  /dev/disk/by-id/ata-ST1000DM003-1CH162_S1DAH4PG
```

Разбор флагов:

- **`/dev/disk/by-id/...`, а не `/dev/sdb`.** Имена `sdX` раздаёт ядро в порядке обнаружения — воткнул флешку, поменял порт, и вчерашний `sdb` стал `sdc`. ZFS переживёт это и по метке на диске, но читать `zpool status` станет невозможно. `by-id` содержит серийный номер и не меняется никогда. Это главная ошибка новичков в ZFS.
- **`ashift=12`** — размер блока 2¹² = 4 КБ. Оба диска сообщают логический сектор 512 Б, а физический 4096 Б (`cat /sys/block/sdb/queue/physical_block_size`), то есть врут ради совместимости. С `ashift=9` каждая запись превратилась бы в чтение-модификацию-запись. **Задаётся только при создании и не меняется никогда** — ошибку тут лечат только пересозданием пула.
- **`-O` против `-o`.** Маленькая — свойство *пула*, большая — наследуемое свойство *датасетов*. `ashift` — свойство пула, `compression` наследуется вниз.
- **`compression=zstd`** — на современных CPU сжатие быстрее диска: меньше байт на пластину = выше эффективная скорость. На уже сжатом (видео, фото) ZFS сам определит несжимаемость и не будет тратить такты.
- **`atime=off`** — не писать время последнего доступа. Иначе любое чтение порождает запись.
- **`xattr=sa` + `acltype=posixacl`** — расширенные атрибуты в самой записи, а не отдельным скрытым файлом. Нужно для samba и заметно быстрее.

### 6. Датасеты

Датасет — не папка, а отдельная ФС со своими свойствами, квотой и снапшотами. Гранулярность снапшотов и репликации = датасет, поэтому дробить стоит по ролям.

```bash
sudo zfs create tank/media                       # для Jellyfin
sudo zfs create tank/files                       # общая шара
sudo zfs create tank/git                         # bare-репозиторий nixos.git
sudo zfs create -o recordsize=1M tank/archive    # крупные файлы

sudo zfs set recordsize=1M tank/media            # медиа читается большими кусками
sudo chown -R gadjet:users /tank
zfs list
```

`recordsize=1M` для медиа: дефолтные 128 КБ означают восемь операций там, где хватило бы одной. Для баз данных наоборот — уменьшают.

### 7. Samba

```bash
sudo smbpasswd -a gadjet      # пароль ставится императивно, в git не попадает
```

Шары `media` и `files` описаны в `modules/storage.nix`. Пароль samba **отдельный** от системного и хранится в `/var/lib/samba/`, а не в конфиге — поэтому его нельзя объявить декларативно, не положив секрет в репозиторий.

`services.samba-wsdd` включён специально: в Windows 10/11 старый NetBIOS-браузер отключён, и без WS-Discovery шара не появится в «Сетевом окружении» (хотя по `\\kitjet\media` откроется).

### 8. Вернуть данные

```bash
sudo rsync -a --info=progress2 /home/gadjet/_migration/ /tank/files/
sudo chown -R gadjet:users /tank/files
rm -rf /home/gadjet/_migration        # только после проверки!
```

### 9. Проверить

```bash
zpool status tank            # ONLINE, оба диска, нет ошибок
zpool list                   # сколько занято/свободно
zfs list -o name,used,avail,compressratio
systemctl status zfs-scrub.timer
```

## Как это чинится, когда сломается

**Диск умер.** `zpool status` покажет `DEGRADED` и виновника. Замена:

```bash
sudo zpool replace tank /dev/disk/by-id/<старый> /dev/disk/by-id/<новый>
zpool status tank      # идёт resilver, проценты видны здесь
```

Пул всё это время работает и доступен.

**Пул не импортировался после перезагрузки.** Смотреть `journalctl -u zfs-import-tank`. Почти всегда — сменившийся `hostId` или диск, который не успел появиться к моменту импорта.

**Свободное место кончилось не там, где ожидалось.** `zfs list -o space` — снапшоты занимают место, но в `du` не видны.

Не делать:

- Не заполнять пул выше ~80 %: ZFS — copy-on-write, при нехватке места фрагментация растёт лавинообразно.
- Не менять `ashift` и `hostId` после создания.
- Не собирать пул по `/dev/sdX`.
