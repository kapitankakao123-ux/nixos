# CLAUDE.md

Репозиторий конфигураций NixOS для домашней инфраструктуры. Одна кодовая база на все машины.

## Машины

| Хост | Арх | Состояние | Роль | Оболочка |
|---|---|---|---|---|
| `kitjet` | x86_64 | работает | домашний сервер: ZFS-хранилище, libvirt/KVM, кино в браузере + Jellyfin, рабочее место | niri + DMS |
| `gadnix` | x86_64 | под переустановку (Arch) | игры, браузер, работа: RDP, WinBox, LibreOffice, VS Code | niri + DMS |
| `rpinix` | aarch64 | под переустановку (Debian+Proxmox) | Raspberry Pi 5 8 ГБ: kiosk Home Assistant, aarch64-виртуалки, приёмник реплик ZFS | cage (kiosk) |

Пользователь везде `gadjet`. Стабильная ветка nixpkgs 26.05; `rpinix` собирается из `nixpkgs-unstable`.

## Раскладка

- `flake.nix` — хосты объявлены один раз, из них генерируются и `nixosConfigurations`, и ноды colmena
- `modules/` — что машина умеет (common, desktop, storage, virtualisation, kiosk, backup)
- `home/` — окружение пользователя (home-manager)
- `hosts/<имя>/` — какая машина что включает + `hardware-configuration.nix`
- `docs/` — vault Obsidian: контекст проекта, чек-листы, разбор ошибок. **Начинать чтение с `docs/00-Проект.md`.**

**Пошаговые инструкции всегда оформлять отдельным файлом в `docs/`, а не только ответом в чате** — владелец читает их в Obsidian. В чате остаётся краткая выжимка и статус. В файле с гайдом — команды с объяснением, почему именно так, и раздел «как это чинится».

## Команды

```bash
colmena apply --on <хост>                      # деплой
colmena apply-local                            # локально
sudo nixos-rebuild switch --flake ~/nixos      # локально, по hostname
nix flake update                               # обновить inputs
```

## Правила

- Новый файл **обязан** попасть в git (`git add`), иначе flake его не видит.
- `system.stateVersion` не менять никогда. `networking.hostId` уникален на каждой машине.
- Секреты в репозиторий не коммитить. `sops-nix` пока не подключён — до этого только пути к файлам вне git.
- Общая настройка идёт в `modules/`, специфика машины — в `hosts/`. Дублирование между хостами — сигнал вынести в модуль.
- `~/.config/niri/config.kdl` намеренно НЕ под управлением home-manager. Не переводить без явной просьбы.
- Коммит после успешной сборки, не до.
- LXC не использовать. Вместо него `containers.<имя>` (systemd-nspawn) или `virtualisation.oci-containers`.
- На `rpinix` только aarch64-гости: KVM там не эмулирует, x86-образы не запустятся.
- При добавлении опции проверять, импортирован ли объявляющий её модуль: «option does not exist» почти всегда значит отсутствующий импорт, а не опечатку.

## Стиль

- Комментарии в конфигах на русском.
- Владелец учится NixOS: объяснять, почему так, а не только что сделать.
- Не заменять рабочие куски конфига копипастой из интернета — разбираться в существующем.
